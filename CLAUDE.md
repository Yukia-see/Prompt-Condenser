# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What it is

`prompt-condenser`: a Rust + Slint desktop app that condenses ComfyUI prompts, fixes camera-framing / body-part conflicts per checkpoint (Anima, Pony V6, Illustrious, SDXL, SD1.5, Flux), and optionally runs a "deep scan" through an LLM served by **Ollama**, a required runtime dependency (`ollama` + `ollama-vulkan` on Arch for GPU). Ollama can run on this PC or another one on the LAN. Not a git repo. The original design doc lives outside the repo, in the Gemini Antigravity brain folder (`implementation_plan.md`).

## Commands

- Build / run: `cargo build`, `cargo run`
- Tests: `cargo test`; single test: `cargo test turnaround_360` (substring match)
- **Arch package (preferred installer)**: `scripts/build_arch_package.sh [--install]` packs the sources into `packaging/arch/` and runs `makepkg`. The result is `packaging/arch/prompt-condenser-<ver>-1-x86_64.pkg.tar.zst`; `--install` also installs it with its dependencies (ollama, ollama-vulkan, vulkan-tools, xdg-desktop-portal, Slint's Wayland/X11/EGL libs). The package ships the binary, a desktop entry, an icon (`packaging/`) and an Ollama systemd drop-in that waits for a Vulkan GPU at boot. `pkgver` is synced from `Cargo.toml`.
- Run with a prompt preloaded: `prompt-condenser "1girl, …"`
- **Batch captions for LoRA datasets**: `prompt-condenser --caption <folder> [--threshold 0.30] [--overwrite] [--recursive]` (`src/caption.rs`) writes `<image>.txt` next to every image with the fast Tagger mode (one tagger pass + `ai_engine::clean_tagger_prompt`: cleanup rules and picture checks), no window, no Ollama. Existing captions are skipped unless `--overwrite`; captions are unescaped (`kay (girls und panzer)`). Default threshold 0.30 (measured best for this mode; the UI slider stays 0.35 because it also feeds the AI path's hints). Don't point it at `tests/eval_local/`: the answer files have the same names.
- Generic (non-Arch) installer bundle: `scripts/build_installer.sh` → `dist/prompt-condenser-installer{,.tar.gz}` (binary plus `install.sh`; no bundled models). Builds with `-C target-cpu=x86-64-v3` (override via `TARGET_CPU`).
- Install for current user: `./install.sh` (also works from the bundle). It installs and starts Ollama (with an `OLLAMA_VULKAN=1` systemd drop-in), installs the app into `~/.local`, and offers to pull the recommended model (`richardyoung/llama-3.1-8b-instruct-abliterated`) through Ollama. `./install.sh --uninstall` removes the app.

Measurements and the history of removed models/modes are in `CHANGELOG.md`; image-read quality is measured with `tools/eval_images.sh` (local images + answer files in the gitignored `tests/eval_local/`, scored by `tools/score_image_prompts.py`; AI-generated test images live in `tests/eval_local/ai_generated/` and are skipped unless `--all`).

## Architecture

Pipeline: `parser` → `analyzer` → `condenser`, driven from `main.rs`; `ai_engine` is an optional extra pass.

- `parser.rs`: splits the prompt on top-level commas/newlines (respecting `()`, `[]`, `<lora:…>`), unwraps A1111/ComfyUI weight syntax into `PromptToken { weight, had_runaway_weight, original_index, category }`. `TokenCategory`'s declaration order is the output sort order when cleanup is on.
- `profiles.rs`: dropdown enums. **`from_index` values must match the ComboBox order in `ui/app.slint`**. `AiMode` index 2 = AI off, which the UI also hard-codes. `AiModelTier` maps each tier to its Ollama name and its `hf.co/...` pull source.
- `analyzer.rs`: `analyze_with_rules` returns the processed tokens (every suggestion already applied, i.e. mode 0) plus a `PromptChange` list (the cards).
- `condenser.rs`: `build_condensed_output` re-applies each card's `mode` on top of the processed tokens (0 = suggestion, 1 = keep body part and swap framing, 2 = restore original). AI cards (`ChangeAction::AiRewrite`) are opt-in: they start at mode 2 and `apply_ai_card` only edits the prompt once one is accepted. It also emits `highlighted_markdown`, which marks substituted (`PromptToken.replaced`) and added tokens with `<font color><u>`. It's used to list those tags under the After box.
- **The rule-based output never contains tags the user didn't write**, except as direct replacements for one of their tags, and the LoRA tags box (`ScanConfig.lora_tags_raw`, saved in settings). Keep & Emphasize only boosts tags already in the prompt. LoRA tags go into every After view word for word, right after the leading quality tags (`analyzer::insert_lora_block`, applied in `render`, so editing the box doesn't need a rescan). They replace the prompt's own copies and any tag that contradicts them (`tags_conflict`: same last word, same size/length/color attribute; e.g. LoRA `large breasts` drops `gigantic breasts`). The rule output shows a card per conflict; AI text is stripped silently. The AI is told the tags but asked not to repeat them, and rule-based dynamic variations never vary them. Don't reintroduce auto-appended framing/quality/score tags or pinned-tag injection; tests in `analyzer.rs` guard this. New content comes only from the AI, opt-in and highlighted: green = added, amber = substituted (`condenser::Highlight`). The AI Improved prompt is a separate After view (`after_view`).
- `ai_engine/` (`mod.rs` re-exports everything, so callers use `ai_engine::x`): `instructions`, `cards`, `vision`, `polish`, `image_read`, `translate`, `ollama`, `scan`, `cleanup`; the tests stay in `mod.rs`. Ollama HTTP client only; there is no in-process inference.
  - Endpoints: `/api/tags` (model list), `/api/generate` (`format: "json"`, `keep_alive: 30m`; `options.num_gpu: 0` when the mode is CPU only), `/api/ps` (reports GPU vs CPU placement for the status bar).
  - `pull_tier_model`: `/api/pull` of the `hf.co` GGUF, then `/api/copy` under the short name, then `/api/delete` of the long name.
  - Deep scan reply (enforced with a JSON schema in `format`, property order = generation order): `scene_summary`, `scene_breakdown`, `issues`, `improved_prompt` (full rewrite, may add details), `changes` (replace/remove/add/reweight/framing_safe_swap).
  - `convert_ai_changes` turns `changes` into opt-in cards. It drops findings whose `original` isn't in the prompt, that a rule card already covers, or that change nothing. An `original` of `""` means "add". AI card ids start at `AI_CARD_ID_BASE`.
  - Replies that hit the output limit are repaired: `close_truncated_json` keeps everything up to the last complete value, and only fully written changes are kept. Unreadable replies are retried. Every scan is then checked for completeness (`scan_problems`): a scene summary plus at least 4 breakdown fields, a negative of 5 or more tags (not for Flux), at least one card that survives `convert_ai_changes` whenever the rewrite differs from the prompt, and `{…}` groups when dynamic is on. Missing parts trigger up to 2 re-scans, and `merge_scan` fills only the gaps (the rewrite, its cards and its dynamic version are taken together). The status badge shows "re-scanned N×" and anything still missing.
  - Models (since 0.4.2): `AiModelTier::ALL` = `Good` (Gemma 4 E4B, `prompt-condenser-gemma4-e4b`), `Better` (Llama 3.1 8B Abliterated, `richardyoung/llama-3.1-8b-instruct-abliterated`, instruction family `Generic`) and `Best` (`huihui_ai/gemma-4-abliterated:12b`); the app preselects the last installed one. Registry names are pulled as they are (`pull_tier_model` only copies when the name differs from the source). Light (E2B) and the `prompt-condenser-gemma4-12b` name were dropped; users who have the old name still see it as an "other model". `Better` and the new `Best` build were not part of the benchmarks below: run `AUDIT_MODEL=<name> cargo test live_audit -- --ignored --nocapture` against a tier before recommending it. Image reading uses a separate vision encoder (`vision_model()` in `main.rs`: Qwen-VL 3B, then Moondream, then a vision-capable model); dedicated encoders (`is_dedicated_encoder`) get `keep_alive` 30 s and are unloaded before the text model runs (`unload_dedicated_encoders`), because three resident models don't fit this shared-memory GPU.

Guarded by `instructions_do_their_job` and `instructions_follow_the_model_family`.

Guarded by `dual_pass_honors_the_selected_mode`.
